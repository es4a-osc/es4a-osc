# 扩展类库使用

> 使用指南｜核对日期：2026-10-08｜依据：当前 SDK 加载、编译器类库消费与真实项目样例｜适用范围：使用已有类库开发 Simple 应用。

本页说明使用扩展类库的通用流程。具体类库、类型、成员和样例随对应版本提供，不在网站固定列出当前类库名单或逐库维护演示。

## 查阅与准备

1. 按[环境准备](tutorial/environment.md#选择-sdk)选择完整 SDK，在 ES4A 的“类库”视图确认需要的类库已加载。
2. 展开分类、类型和成员，结合代码补全、悬停说明和参数提示查阅所用版本的 API。
3. 阅读该版本随附的样例及使用要求，确认依赖、项目参数、资源、设备条件和权限。SDK 类库目录中的 `sample/project.properties` 是已有样例常用的项目入口；实际是否提供、目录位置和内容以发行版本为准。

使用已有 SDK 中的类库不需要先学习 Java 实现或清单定义。类库未提供或交付不完整时，应取得包含所需能力的兼容 SDK，而不是只添加一个名称相似的提示定义。

## 在项目中调用

使用完整限定名引用扩展类型，或在单元头部声明 `别名`。普通对象在允许创建时取得实例；组件在设计器添加。实例函数通过实例调用，静态函数通过类型调用，扩展静态函数不会仅因出现在类库树中就自动成为全局函数。

组件、属性和事件的通用操作见[核心 API 使用](api/README.md)。别名和类型的写法见[别名声明](simple/Simple语言定义.md#别名声明)；不要通过手写单元属性区绕过设计器添加组件。

类库有额外项目参数时，按该版本提供的名称和值填写 `project.properties`。资源、资产与依赖遵循所用 SDK 的交付说明，不凭类库名称猜测文件、参数或权限。

## 编译与运行

保存代码和设计器修改后[编译并运行项目](tutorial/build.md)，以正式编译结果确认类型及成员可调用。类库树可见只证明元数据已读取，不证明实际代码、依赖或资源完整。

需要权限或系统设置的功能，运行时检查授权与拒绝情况。事件回调、异步任务和组件销毁后的行为按该版本要求处理，设备运行成功后才能确认实际效果。

## 更换版本

更换 SDK 后重新选择入口并刷新类库，核对本项目引用的类型、成员、项目参数与依赖，再重新编译和验证。保留原 SDK 与可运行项目，便于比较变化。

提示与编译不一致时按[常见问题](tutorial/faq.md#界面有补全但编译失败)排查。需要追溯具体实现或样例时，从[SDK 仓库](https://gitee.com/es4a/sdk)进入对应类库和版本；其他版本的演示不能作为当前接口保证。
